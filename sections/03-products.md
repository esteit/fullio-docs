# 3. Товары

## 3.1. Методы

| Метод              | Назначение                             |
|--------------------|----------------------------------------|
| `product.list`     | Список товаров                         |
| `product.get`      | Карточка товара                        |
| `product.create`   | Создать черновик                       |
| `product.update`   | Изменить товар                         |
| `product.activate` | Активировать товар без ручной проверки |
| `product.archive`  | Архивировать товар                     |

Фото передаются через [файловый API](08-files.md).

## 3.2. Статусы

| Статус     | Значение                                                          |
|------------|-------------------------------------------------------------------|
| `draft`    | Черновик клиента. Нельзя использовать в новых поставках и заказах |
| `active`   | Товар готов к поставкам, хранению и заказам                       |
| `blocked`  | Операции временно запрещены Fullio; остатки и история доступны    |
| `archived` | Товар выведен из работы; доступен только для чтения и истории     |

Ручной проверки или отдельного признака ожидания проверки нет. Клиент активирует
корректно заполненный черновик методом `product.activate`. Блокировку и снятие
блокировки выполняет Fullio внутренними средствами.

`tracking_mode` оставлен в контракте для будущего расширения. В текущей версии
поддерживается только значение `lot` — обязательный учёт партий. Другие значения
возвращают `VALIDATION_FAILED`.

Флаг `uses_honest_sign` показывает, что товар подлежит маркировке «Честный знак».
Он не влияет на `tracking_mode`: маркированные товары также учитываются по партиям.
При приёмке флаг служит внутренней инструкцией сотруднику Fullio визуально
проверить наличие кодов на товаре; результат этой проверки в API не возвращается.
При сборке или упаковке коды сканируются и затем возвращаются в информации о
заказе.

## 3.3. Объект `product`

| Поле                                 | Тип          | Описание                           |
|--------------------------------------|--------------|------------------------------------|
| `id`                                 | integer      | ID Fullio                          |
| `sku`                                | string       | Уникален внутри компании           |
| `name`                               | string       | Название                           |
| `description`                        | string/null  | Описание                           |
| `category`                           | string/null  | Категория                          |
| `status`                             | string       | Статус                             |
| `tracking_mode`                      | string       | Режим учёта                        |
| `weight_grams`                       | integer/null | Вес                                |
| `length_mm`, `width_mm`, `height_mm` | integer/null | Габариты                           |
| `is_fragile`                         | boolean      | Хрупкий товар                      |
| `uses_honest_sign`                   | boolean      | Используется «Честный знак»        |
| `check_expiry_on_picking`            | boolean      | Проверять срок годности при сборке |
| `packing_instructions`               | string/null  | Требования к упаковке              |
| `min_stock_level`                    | integer      | Минимальный остаток                |
| `barcodes`                           | array        | Объекты `product_barcode`          |
| `photos`                             | array        | Ссылки на `file`                   |
| `available_actions`                  | array        | Доступные действия                 |
| `created_at`, `updated_at`           | datetime     | Время создания и изменения         |

`check_expiry_on_picking: true` требует, чтобы Fullio проверил напечатанный на
товаре срок годности перед завершением сборки. Просроченный товар или товар с
нечитаемым сроком не используется в заказе: он блокируется, а склад пытается
выбрать другую партию. Флаг не делает дату срока годности обязательной при
создании товара или поставки.

`min_stock_level` используется только для мониторинга. Товар считается имеющим
низкий остаток, когда его доступное количество меньше `min_stock_level`. Значение
`0` отключает предупреждение. Порог не запрещает резервирование и не создаёт
поставку автоматически.

### 3.3.1. Объект `product_barcode`

`product_barcode` — постоянный штрихкод SKU, по которому Fullio распознаёт товар
при приёмке и других складских операциях. Он возвращается внутри `product.barcodes`.

| Поле         | Тип      | Описание                                                        |
|--------------|----------|-----------------------------------------------------------------|
| `id`         | integer  | ID Fullio; только в ответе                                      |
| `barcode`    | string   | Значение штрихкода без пробелов                                 |
| `type`       | string   | Источник штрихкода                                              |
| `is_primary` | boolean  | Основной штрихкод товара                                        |
| `is_active`  | boolean  | Можно ли использовать для распознавания товара; только в ответе |
| `created_at` | datetime | Время добавления; только в ответе                               |

Типы:

| Тип            | Значение                                            | Кто передаёт  |
|----------------|-----------------------------------------------------|---------------|
| `manufacturer` | GTIN, EAN или другой код, нанесённый производителем | Клиент        |
| `client`       | Собственный постоянный штрихкод компании-клиента    | Клиент        |
| `internal`     | Внутренний складской штрихкод Fullio                | Только Fullio |

Правила:

- значение уникально среди товаров одной компании;
- у товара может быть несколько активных штрихкодов;
- ровно один активный штрихкод является основным;
- основной штрихкод нельзя деактивировать;
- для активации товара нужен хотя бы один активный штрихкод;
- клиент может создавать и изменять только типы `manufacturer` и `client`;
- удалённый из переданного набора клиентский штрихкод деактивируется, но остаётся
  в истории;
- индивидуальные коды «Честного знака» не являются штрихкодами товара и в
  `product.barcodes` не хранятся.

Типа `marketplace` в текущем API нет. Штрихкод этикетки конкретной площадки нельзя
однозначно описать без самой площадки и её идентификаторов товара. Такая модель
должна добавляться вместе с интеграциями с маркетплейсами.

## 3.4. `product.list`

Фильтры:

- `search` — SKU, название или штрихкод;
- `status[]`;
- `low_stock`;
- `updated_since`.

Сортировка: `sku`, `name`, `created_at`, `updated_at`.

```json
{
  "method": "product.list",
  "params": {
    "filter": {
      "status": ["active"],
      "search": "футболка"
    },
    "sort": {
      "field": "updated_at",
      "direction": "desc"
    },
    "pagination": {
      "limit": 50,
      "cursor": null
    }
  }
}
```

Результат содержит `products[]` и `pagination`.

## 3.5. `product.get`

```json
{
  "method": "product.get",
  "params": {
    "product": {
      "id": 101
    }
  }
}
```

Результат: `result.product`.

## 3.6. `product.create`

Обязательны `sku`, `name`. Остальные поля необязательны; булевы признаки по умолчанию равны `false`, `tracking_mode` — `lot`, `min_stock_level` — `0`. Если `tracking_mode` передан явно, он должен быть равен `lot`.

```json
{
  "method": "product.create",
  "params": {
    "product": {
      "sku": "TSHIRT-BLACK-M",
      "name": "Футболка чёрная, размер M",
      "category": "Одежда",
      "tracking_mode": "lot",
      "weight_grams": 240,
      "length_mm": 300,
      "width_mm": 250,
      "height_mm": 30,
      "is_fragile": false,
      "uses_honest_sign": true,
      "check_expiry_on_picking": true,
      "min_stock_level": 20,
      "barcodes": [
        {
          "barcode": "4600000000001",
          "type": "manufacturer",
          "is_primary": true
        }
      ],
      "photos": [
        {
          "id": 501
        }
      ]
    }
  }
}
```

Результат: `result.product` в статусе `draft`.

Ошибки: `DUPLICATE_SKU`, `DUPLICATE_BARCODE`, `FILE_NOT_READY`, `VALIDATION_FAILED`.

## 3.7. `product.update`

```json
{
  "method": "product.update",
  "params": {
    "product": {
      "id": 101,
      "patch": {
        "weight_grams": 250,
        "packing_instructions": "Упаковывать в непрозрачный пакет"
      }
    }
  }
}
```

Переданный `barcodes` или `photos` является полным новым набором. Отсутствующее поле не изменяет текущий набор. Для `barcodes` заменяется только набор типов `manufacturer` и `client`; внутренние штрихкоды Fullio сохраняются.

## 3.8. `product.activate`

```json
{
  "method": "product.activate",
  "params": {
    "product": {
      "id": 101
    }
  }
}
```

Метод проверяет обязательные складские данные и переводит корректный `draft` в
`active` без ручного согласования Fullio. При ошибке статус не изменяется, API
возвращает `VALIDATION_FAILED` с `field_errors`. Повторная активация уже активного
товара возвращает его текущее состояние и не создаёт отдельную операцию.

## 3.9. `product.archive`

```json
{
  "method": "product.archive",
  "params": {
    "product": {
      "id": 101
    }
  }
}
```

Архивация не удаляет товар, остатки и историю. Возможность архивирования определяется `available_actions`.
