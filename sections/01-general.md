# 1. Общие правила

## 1.1. Транспорт и авторизация

Все запросы выполняются методом `POST` на `/api/v1/jsonrpc`.

| Заголовок                        | Обязателен | Назначение                                       |
|----------------------------------|-----------:|--------------------------------------------------|
| `Content-Type: application/json` |         да | Формат тела запроса                              |
| `X-Authorization-Token`          |         да | API-ключ компании                                |
| `X-Request-Id`                   |        нет | Идентификатор запроса в сервисе личного кабинета |
| `X-External-User-Id`             |        нет | Идентификатор пользователя для аудита            |

API-ключ нельзя передавать в браузер, мобильное приложение, URL или публичные журналы. `X-External-User-Id` используется только для аудита и не влияет на авторизацию.

## 1.2. JSON-RPC

```json
{
  "jsonrpc": "2.0",
  "id": "unique-request-id",
  "method": "product.get",
  "params": {
    "product": {
      "id": 101
    }
  }
}
```

- `jsonrpc` всегда равен `2.0`;
- `id` — строка или число, уникальное в пределах вызывающей системы;
- `method` чувствителен к регистру;
- `params` всегда является объектом;
- компания не передаётся в `params` и определяется по ключу.

## 1.3. Именованные сущности

Сущность нельзя передавать непосредственно в корне `params` или `result`. Она всегда находится под ключом с именем сущности.

```json
{
  "params": {
    "product": {
      "id": 101,
      "patch": {
        "name": "Новое название"
      }
    }
  }
}
```

```json
{
  "result": {
    "product": {
      "id": 101,
      "sku": "TSHIRT-BLACK-M",
      "name": "Новое название"
    }
  }
}
```

Коллекции возвращаются под предметным именем: `products`, `inventory`, `movements`, `inbounds`, `orders`, `problems`, `returns`, `charges`, `invoices`.

## 1.4. Изоляция компаний

Любой объект ищется одновременно по переданному идентификатору и компании API-ключа. Если ID принадлежит другой компании, API возвращает `ENTITY_NOT_FOUND` и не раскрывает существование объекта.

## 1.5. Идентификаторы

- внутренний `id` Fullio — положительное целое число;
- бизнес-номера (`sku`, `shipment_number`, `external_order_id`, `order_number`) — строки;
- бизнес-номер не заменяет внутренний `id`, если метод явно не разрешает такой поиск.

Ссылка на сущность оформляется объектом:

```json
{
  "product": {
    "id": 101
  }
}
```

## 1.6. Даты и единицы измерения

- дата: `YYYY-MM-DD`;
- дата и время: ISO 8601 в UTC, например `2026-08-18T10:30:00Z`;
- количество товара — целое число;
- вес — граммы;
- размеры — миллиметры;
- деньги — объект `Money` с целым количеством копеек.

```json
{
  "amount": 8500000,
  "currency": "RUB"
}
```

## 1.7. Обновление сущностей

Изменение выполняется через `patch`:

- отсутствующее поле — не изменять;
- `null` — очистить поле, если это разрешено;
- пустая строка не используется вместо `null`;
- неизвестные поля возвращают `VALIDATION_FAILED`.

## 1.8. Пагинация и сортировка

```json
{
  "params": {
    "filter": {},
    "sort": {
      "field": "updated_at",
      "direction": "desc"
    },
    "pagination": {
      "limit": 50,
      "cursor": null
    }
  }
}
```

Ответ:

```json
{
  "result": {
    "products": [],
    "pagination": {
      "next_cursor": null,
      "has_more": false
    }
  }
}
```

- `limit` по умолчанию — 50, максимум — 100;
- cursor является непрозрачной строкой;
- фильтры и сортировка не меняются при переходе на следующую страницу;
- допустимые поля сортировки перечисляются в разделе метода.

## 1.9. Доступные действия

Карточка сущности возвращает `available_actions`. Личный кабинет использует этот список для отображения кнопок и не воспроизводит переходы статусов самостоятельно.

```json
{
  "status": "draft",
  "available_actions": ["update", "submit", "cancel"]
}
```

Сервер всё равно повторно проверяет возможность действия в момент запроса.

## 1.10. Ошибки

```json
{
  "jsonrpc": "2.0",
  "id": "request-17",
  "error": {
    "code": -32010,
    "message": "Поставка не может быть отменена",
    "data": {
      "error_code": "INVALID_STATUS_TRANSITION",
      "request_id": "request-17",
      "field_errors": [],
      "details": {
        "entity": "inbound",
        "entity_id": 701,
        "status": "receiving"
      }
    }
  }
}
```

Клиент принимает решение по стабильному `error_code`, а не по тексту `message`.

| `error_code`                | Значение                              |
|-----------------------------|---------------------------------------|
| `AUTHENTICATION_FAILED`     | Ключ отсутствует, неверен или отозван |
| `COMPANY_DISABLED`          | Компания отключена                    |
| `ACCESS_DENIED`             | Ключ не разрешает действие            |
| `VALIDATION_FAILED`         | Ошибка входных данных                 |
| `ENTITY_NOT_FOUND`          | Объект не найден в компании ключа     |
| `INVALID_STATUS_TRANSITION` | Действие запрещено в текущем статусе  |
| `DUPLICATE_BUSINESS_KEY`    | Бизнес-номер уже используется         |
| `FILE_NOT_READY`            | Файл ещё не загружен или не обработан |
| `RATE_LIMIT_EXCEEDED`       | Превышен лимит запросов               |
| `INTERNAL_ERROR`            | Неожиданная ошибка Fullio             |

Ошибка поля:

```json
{
  "field": "inbound.lines[0].expected_quantity",
  "code": "POSITIVE_INTEGER_REQUIRED",
  "message": "Количество должно быть больше нуля"
}
```

## 1.11. Версионирование

Major-версия находится в URL: `/api/v1/jsonrpc`.

Новый метод или необязательное поле являются совместимым изменением. Удаление, переименование или изменение смысла существующего поля требует новой major-версии.
