# 5. Поставки: оставшиеся требования

Реализованный API поставок описан в **API → Поставки** личного кабинета
(`/company-{companyId}/api/arrivals`). Его контракт удалён из этого проекта.
Ниже сохранены только отложенные требования; они не описывают доступные API-поля.

## Отложенный партионный учёт

Решением от 29 октября 2026 года подтверждён количественный учёт `quantity`.
Физическое разделение партий и публичные номера партий Fullio и производителя
отложены вместе с режимом `lot`. Это не требование к текущему выпуску API.
Внутренний `InventoryLot` используется для происхождения товара и расчётного
распределения; он не означает физического разделения производственных партий.

Сохранённые требования для будущего партионного режима:

- несколько производственных партий одного товара в одной поставке;
- собственный номер партии Fullio (`lot_number`), в том числе без номера производителя;
- необязательный номер партии производителя (`manufacturer_lot_number`);
- связь партии с поставкой и приёмкой, количество, брак и время приёмки;
- согласование сумм партий с итогом соответствующей строки поставки.

Прежние примеры `inbound_lot` удалены: публичный контракт партий потребуется
согласовать при реализации режима `lot`.

## Отложенные описания склада

Пояснения склада к конкретной приёмке и её строкам ведутся в
[задаче #37, пункт 8](https://github.com/esteit/fullio/issues/37).
До реализации нужно определить видимость для клиента и правила редактирования
после фиксации приёмки. Это отдельная потребность от общего комментария клиента
к поставке; клиентский комментарий строки из прежнего draft не добавляется.

## Начисления по поставке (`charges_summary`)

Оставлено до реализации биллинга по решению от 29 октября 2026 года.


| Поле              | Тип     | Описание                        |
|-------------------|---------|---------------------------------|
| `count`           | integer | Количество связанных начислений |
| `amount`          | Money   | Общая сумма начислений          |
| `disputed_amount` | Money   | Сумма оспариваемых начислений   |

Будущая полная детализация предусмотрена через [`charge.list`](10-billing.md#105-chargelist) с
фильтром по связанной поставке.
