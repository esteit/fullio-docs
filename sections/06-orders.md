# 6. Заказы

## 6.1. Методы

| Метод          | Назначение                          |
|----------------|-------------------------------------|
| `order.list`   | Список заказов                      |
| `order.get`    | Карточка заказа                     |
| `order.create` | Создать черновик                    |
| `order.update` | Изменить разрешённые данные         |
| `order.submit` | Передать заказ Fullio               |
| `order.cancel` | Отменить заказ или запросить отмену |

Резервирование, сборка, упаковка и отгрузка выполняются Fullio и не являются публичными методами.

## 6.2. Статусы

| Статус          | Значение                                           |
|-----------------|----------------------------------------------------|
| `draft`         | Черновик клиента; Fullio ещё не обрабатывает заказ |
| `new`           | Заказ передан Fullio и ожидает начала обработки    |
| `in_progress`   | Выполняется резервирование, сборка или упаковка    |
| `ready_to_ship` | Заказ упакован и готов к передаче в доставку       |
| `shipped`       | Заказ передан в доставку                           |
| `problem`       | К заказу заведена активная проблема                |
| `cancelled`     | Заказ отменён                                      |

При создании активной проблемы заказ переходит в `problem`. После её решения он
возвращается на подходящий этап обработки либо отменяется.

Внутренние этапы возвращаются в `timeline`, а не расширяют список клиентских статусов.

## 6.3. Состав заказа

| Поле                | Описание                                        |
|---------------------|-------------------------------------------------|
| `id`                | ID Fullio                                       |
| `external_order_id` | Стабильный ID заказа в системе клиента          |
| `order_number`      | Отображаемый номер                              |
| `status`            | Клиентский статус                               |
| `shipping`          | Переданные интегратором данные доставки и лейбл |
| `lines`             | Товары, количества и коды «Честного знака»      |
| `problems`          | Связанные проблемы                              |
| `charges_summary`   | Начисления по заказу                            |
| `timeline`          | История обработки                               |
| `available_actions` | Доступные действия                              |

Уникальность: `company + external_order_id`.

### 6.3.1. Объект `shipping`

Fullio не рассчитывает доставку и не создаёт лейбл. Готовые данные передаёт
интегратор.

| Поле              | Тип         | Описание                                               |
|-------------------|-------------|--------------------------------------------------------|
| `provider`        | string      | Служба доставки, например `cdek`                       |
| `method`          | string/null | Способ доставки или название тарифа                    |
| `tracking_number` | string/null | Трек-номер, если уже известен                          |
| `ship_by_date`    | date/null   | Крайняя дата передачи заказа в доставку                |
| `label_file_id`   | integer     | ID готового файла лейбла; только в `create` и `update` |
| `label_file`      | object      | Объект `file`; только в ответе                         |
| `comment`         | string/null | Инструкция интегратора для склада                      |

Лейбл предварительно загружается через [файловый API](08-files.md) с назначением
`shipping_label`. К моменту `order.submit` файл должен иметь статус `ready`.

## 6.4. `order.list`

Фильтры:

- `search` — номер заказа, внешний ID или трек-номер;
- `status[]`;
- `created_from`, `created_to`;
- `ship_by_from`, `ship_by_to`;
- `has_problem`;
- `updated_since`.

Сортировка: `order_number`, `created_at`, `updated_at`, `ship_by_date`, `shipped_at`.

Результат содержит `orders[]` и `pagination`.

## 6.5. `order.get`

```json
{
  "method": "order.get",
  "params": {
    "order": {
      "id": 1001
    }
  }
}
```

Результат: `result.order` с данными `shipping`, строками, проблемами и timeline.

## 6.6. `order.create`

```json
{
  "method": "order.create",
  "params": {
    "order": {
      "external_order_id": "shop-45001",
      "order_number": "45001",
      "shipping": {
        "provider": "cdek",
        "method": "courier",
        "tracking_number": "1234567890",
        "ship_by_date": "2026-08-20",
        "label_file_id": 901,
        "comment": "Передать курьеру до 18:00"
      },
      "lines": [
        {
          "product": {
            "id": 101
          },
          "quantity": 2
        }
      ],
      "comment": "Позвонить перед доставкой"
    }
  }
}
```

Если `external_order_id` уже используется внутри компании, API возвращает `DUPLICATE_EXTERNAL_ORDER_ID`.

`order.create` сохраняет переданные данные без запуска резервирования и возвращает
`result.order` в статусе `draft`. Полная проверка получателя, доставки и состава
выполняется методом `order.submit`.

## 6.7. Строка заказа

```json
{
  "id": 1101,
  "product": {
    "id": 101,
    "sku": "TSHIRT-BLACK-M",
    "name": "Футболка чёрная, размер M"
  },
  "quantity": 2,
  "reserved_quantity": 2,
  "picked_quantity": 0,
  "shipped_quantity": 0,
  "status": "reserved",
  "honest_sign_codes": []
}
```

Количество резерва, сборки и отгрузки нельзя передавать в `create` или `update`.
`honest_sign_codes` также нельзя передавать при создании или изменении заказа.
Для товара с требованием маркировки (`requires_marking: true`) Fullio заполняет этот массив кодами,
отсканированными во время сборки или упаковки. До сканирования массив пуст.

```json
{
  "id": 1101,
  "product": {
    "id": 101,
    "sku": "TSHIRT-BLACK-M",
    "name": "Футболка чёрная, размер M"
  },
  "quantity": 2,
  "reserved_quantity": 2,
  "picked_quantity": 2,
  "shipped_quantity": 0,
  "status": "packed",
  "honest_sign_codes": [
    {
      "code": "010460000000000121ABC123",
      "scanned_at": "2026-08-20T10:15:00Z"
    },
    {
      "code": "010460000000000121ABC124",
      "scanned_at": "2026-08-20T10:15:04Z"
    }
  ]
}
```

Коды доступны через `order.get` сразу после сканирования и остаются в истории
заказа после отгрузки. Для остальных товаров массив всегда пуст.

Для товара с `check_expiry_on_picking: true` строка не может перейти в состояние
`picked`, пока сотрудник Fullio не подтвердит проверку срока годности. Просроченный
товар или товар с нечитаемым сроком блокируется; склад выбирает другую партию. Если
доступного товара недостаточно, заказ получает проблему.

## 6.8. `order.update`

```json
{
  "method": "order.update",
  "params": {
    "order": {
      "id": 1001,
      "patch": {
        "shipping": {
          "provider": "cdek",
          "method": "courier",
          "tracking_number": "1234567890",
          "ship_by_date": "2026-08-21",
          "label_file_id": 902,
          "comment": "Использовать обновлённый лейбл"
        }
      }
    }
  }
}
```

Изменяемые поля определяются `available_actions` и текущим этапом. После начала
сборки изменение состава заказа и данных `shipping` запрещено.

## 6.9. `order.submit`

Проверяет черновик, включая наличие готового лейбла, переводит его из `draft` в
`new` и передаёт Fullio. После этого начинается резервирование; его результат
отражается в строках заказа и timeline.

```json
{
  "method": "order.submit",
  "params": {
    "order": {
      "id": 1001
    }
  }
}
```

При неполных или некорректных данных статус не изменяется, API возвращает
`VALIDATION_FAILED` с `field_errors`. Повторная отправка уже переданного заказа не
запускает резервирование повторно и возвращает текущее состояние заказа.

## 6.10. `order.cancel`

```json
{
  "method": "order.cancel",
  "params": {
    "order": {
      "id": 1001,
      "reason": "Покупатель отказался"
    }
  }
}
```

Поведение:

- `draft` — немедленная отмена;
- `new` — немедленная отмена;
- после резерва — отмена со снятием резерва;
- `in_progress` — может создать запрос на подтверждение;
- `ready_to_ship` — может требовать платной операции;
- `shipped` — отмена запрещена, используется возврат.

Результат возвращает обновлённый `result.order`. Если требуется решение Fullio, заказ получает подходящий статус, а в `problems` появляется кейс.

## 6.11. Timeline

События timeline: `created`, `submitted`, `reserved`, `reservation_failed`,
`picking_started`, `picked`, `packed`, `ready_to_ship`, `handed_over`, `shipped`,
`cancel_requested`, `cancelled`, `problem`.

Отдельной сущности отправления в текущем API нет. Статус доставки определяется по
статусу заказа, а лейбл и трек-номер находятся в `order.shipping`.
