# 4. Остатки и движения

## 4.1. Реализованный API

Текущий контракт `inventory.list` и `inventory.movements`, поля, фильтры,
сортировки и примеры описаны в [API остатков в ЛК](../../fullio/templates/company/_api_inventory.html.twig).

## 4.2. Нереализованные требования для обсуждения

Следующие требования сохранены из прежнего draft. Они не входят в текущий
API; необходимость и окончательный контракт каждого пункта требуют решения.

- `min_stock_level` и `is_low_stock`: признак нехватки равен `true`, когда
  `min_stock_level > 0` и доступный остаток товара меньше `min_stock_level`.
  Для расчёта используется доступный к резервированию остаток по всем
  расчётным партиям товара; заблокированный, повреждённый и зарезервированный
  товар исключён.
- Фильтры `low_stock`, `has_available` и `has_problem`. Состав проблем для
  `has_problem` ещё нужно определить.
- `last_movement_at`, `updated_at` и сортировка остатка по `updated_at`.
- Фильтр `updated_since` и стабильная инкрементальная синхронизация остатков —
  совместно с [задачей #47](https://github.com/esteit/fullio/issues/47).
- Связи движений с будущими [заказами](06-orders.md) и
  [возвратами](09-returns.md): резерв и снятие резерва заказа, поступление
  возврата, ссылки на соответствующие документы. Прежнее правило исключения
  товара из остатка после упаковки требует отдельного решения вместе с
  процессом заказа; текущий API исключает отгруженный товар.
- Публичный `comment` движения: решить, нужен ли он и какой текст можно
  возвращать. Текущий API такого поля не содержит.
