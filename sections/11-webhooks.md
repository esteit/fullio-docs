# 11. Webhooks

Webhook уведомляет интегратора об изменении данных. Полная сущность в webhook не
передаётся: получив событие, интегратор запрашивает её актуальное состояние через
JSON-RPC API.

URL получателя и секрет подписи настраиваются при подключении интегратора. Методов
управления webhook в текущем клиентском API нет.

## 11.1. HTTP-запрос

Fullio выполняет `POST` на настроенный HTTPS URL.

```http
Content-Type: application/json
X-Fullio-Event-Id: evt_01J60000000000000000000001
X-Fullio-Timestamp: 1787047200
X-Fullio-Signature: sha256=4a1f...
```

Тело:

```json
{
  "id": "evt_01J60000000000000000000001",
  "type": "order.updated",
  "created_at": "2026-08-18T10:00:00Z",
  "company": {
    "id": 25
  },
  "entity": {
    "type": "order",
    "id": 1001
  }
}
```

| Поле          | Тип      | Описание                               |
|---------------|----------|----------------------------------------|
| `id`          | string   | Уникальный ID события для дедупликации |
| `type`        | string   | Тип события                            |
| `created_at`  | datetime | Время создания события                 |
| `company.id`  | integer  | Компания, данные которой изменились    |
| `entity.type` | string   | Тип изменившейся сущности              |
| `entity.id`   | integer  | ID изменившейся сущности               |

## 11.2. Типы событий

| Событие             | Что изменилось | Как получить данные                          |
|---------------------|----------------|----------------------------------------------|
| `product.updated`   | Товар          | `product.get`                                |
| `inventory.updated` | Остаток товара | `inventory.get` по `entity.id` как ID товара |
| `inbound.updated`   | Поставка       | `inbound.get`                                |
| `order.updated`     | Заказ          | `order.get`                                  |
| `problem.updated`   | Проблема       | `problem.get`                                |
| `return.updated`    | Возврат        | `return.get`                                 |
| `invoice.updated`   | Счёт           | `invoice.get`                                |

Одно событие означает, что сущность могла измениться. Оно не описывает конкретную
операцию и не содержит частичное состояние. Интегратор всегда читает актуальную
версию через API.

## 11.3. Подпись

`X-Fullio-Signature` вычисляется как HMAC-SHA256 от строки:

```text
X-Fullio-Timestamp + "." + raw_request_body
```

Ключом является секрет webhook. Результат передаётся в hex с префиксом `sha256=`.
Подпись проверяется по исходным байтам тела до разбора JSON. Сравнение выполняется
за константное время.

Интегратор должен отклонять запросы с неверной подписью и timestamp, отличающимся
от текущего времени более чем на пять минут.

## 11.4. Подтверждение и повторы

- любой HTTP-ответ `2xx` подтверждает получение;
- интегратор должен ответить не позднее чем через 10 секунд;
- при сетевой ошибке, таймауте или другом статусе Fullio повторяет доставку;
- доставка выполняется как минимум один раз, поэтому одно событие может прийти
  повторно;
- интегратор дедуплицирует события по `id`;
- порядок получения разных событий не гарантируется;
- повторная доставка выполняется с увеличивающимся интервалом в течение 24 часов.

Обработчик должен быстро проверить подпись, сохранить событие и вернуть `2xx`.
Запрос сущности и дальнейшая обработка выполняются асинхронно.
